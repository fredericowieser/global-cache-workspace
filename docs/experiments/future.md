# Future directions: training dynamics, rollouts, and cache stability

This document analyzes the empirical performance gap between Cache Processor (CP) adaptation and Full Backbone SFT on multi-step mathematical reasoning, formalizes the theoretical failure modes, and outlines algorithmic paths forward—including rollout-aware Backpropagation Through Time (BPTT), lightweight pure-NLL regularizations, and Reinforcement Learning on Cache States.

## 2. Theoretical diagnosis

Three primary mechanisms explain why BGT underperforms the frozen base model on generative math reasoning despite achieving low training cross-entropy ($\sim 0.43$):

```
                       TRAINING (Teacher-Forced)
 Gold Tokens:   [x_0, ..., x_63] ──▶ Cache S_0 ──▶ [BGT Processor] ──▶ S_0* (Low Loss on x_64..x_127)
                                                          │
──────────────────────────────────────────────────────────┼────────────────────────────────────────
                                                          ▼
                      GENERATION (Autoregressive Rollout)
 Sampled Trace: [x_0, ..., x_63] ──▶ Cache S_0 ──▶ [BGT Processor] ──▶ S_0* (Perturbed Attention)
                                                          │
                                                          ▼ (Next 64 tokens generated with drift)
                [x_64, ..., x_127] ──▶ Cache S_1 ──▶ [BGT Processor] ──▶ S_1* (Compounded Drift)
                                                          │
                                                          ▼ (Repeated 15-30x across 2048 tokens)
                                               Math Reasoning Derails
```

### 2.1 Exposure bias and recursive cache perturbation
- **Teacher-forcing invariant:** During training, every processor call at window boundary $P=64$ operates on cache generated by **100% ground-truth tokens**. The downstream loss is computed on the subsequent ground-truth window.
- **Autoregressive rollout drift:** During generation, tokens are sampled step by step. If generated tokens deviate slightly from the gold distribution, the cache fed into the processor at token 64 is out-of-distribution (OOD).
- **Compounding degradation:** In a 2,048-token math trace, the processor executes **15 to 30 times sequentially**. Each pass applies non-linear updates ($\Delta K, \Delta V$) to an already drifting representation. Rather than filtering noise, high-gain updates amplify deviation, disrupting the frozen backbone's delicate multi-digit arithmetic calibration.
- **Canonical likelihood immunity:** Standard benchmarks (MMLU, ARC, HellaSwag) evaluate short contexts ($< 200$ tokens) via teacher-forced log-likelihood. The processor executes only 0–2 times on clean prompt tokens, resulting in perfect neutrality ($\pm 0.3\%$).

### 2.2 Functional policy vs. working-memory mismatch
- **What math SFT requires:** Multi-step arithmetic requires procedural knowledge and token-transition rules (e.g., carrying digits, sign inversion, equation transformations). In decoder transformers, this procedural computation resides predominantly in the **feedforward network (MLP) weights** ($W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}$) executed at every token step $t \in [1, T]$.
- **What cache processors can do:** Cache Processors are episodic working-memory routers. They adjust historical key-value representations every $P$ tokens over a **completely frozen backbone**. A cache processor can route, emphasize, or consolidate historical context, but it cannot inject new arithmetic logic into frozen MLP layers.

### 2.3 Learning rate and update gain mismatch
- Full-SFT operates at $\text{LR} = 5 \times 10^{-6}$, and LoRA operates at $\text{LR} = 1 \times 10^{-4}$.
- Frozen-backbone Cache Processors trained at $\text{LR} = 1 \times 10^{-3}$ (200× higher than SFT) overfit teacher-forced loss by producing aggressive representation shortcuts (large $\|\Delta K\|_2, \|\Delta V\|_2$).
- In free-running generation, large updates clash with the frozen backbone's query heads ($W_q$), acting as structured noise over the model's native reasoning.

## 3. Backpropagation Through Time (BPTT) and rollout training

### 3.1 Clarifying current BPTT in GCW
In GCW's `forward_windowed_loss`, the autograd computation graph is **not detached** between window segments. Gradients from token 4,000 backpropagate through all intermediate processor calls and prior window activations back to token 1. 

**GCW already executes full BPTT across the sequence.** The limitation is that standard BPTT is unrolled strictly over *oracle teacher-forced trajectories*, not *model rollouts*.

### 3.2 Rollout-aware training paradigms

To enable the Cache Processor to act as an error-dampener and noise-filter during long rollouts, training must expose the processor to self-generated cache states:

#### 1. Scheduled cache sampling (DAgger for KV caches)
During training, window histories are populated with a mixture of ground-truth tokens and model-sampled tokens with probability $p_{\text{sample}}$:
$$\tilde{S}_w = (1 - \alpha) S_w^{\text{gold}} + \alpha S_w^{\text{sampled}}$$
The processor is forced to learn stable transformations that correct historical drift rather than assuming pristine inputs.

#### 2. Reinforcement Learning with Verifiable Rewards (RLVR / GRPO)
Rather than optimizing token-level cross-entropy:
1. Sample complete 2,048-token reasoning trajectories with the Cache Processor active at every $P=64$ cadence.
2. Evaluate final mathematical correctness ($R \in \{0, 1\}$).
3. Update processor parameters via Group Relative Policy Optimization (GRPO) or PPO.
4. **Effect:** The processor is directly optimized to preserve generation stability, penalizing early cache interventions that induce downstream hallucinations.

#### 3. Differentiable unrolled generation
Unrolling discrete generation with Gumbel-Softmax token relaxations across $K$ windows allows true end-to-end gradient flow from generation rewards directly into the cache processor:
$$\mathcal{L}_{\text{rollout}} = \mathbb{E}_{\hat{y}_{1:T} \sim p_\theta(\cdot \mid S^*)} \left[ \text{Loss}(\hat{y}_{1:T}, y^*) \right]$$

## 4. Pure-NLL / Cross-Entropy regularizations (short-term interventions)

Without requiring reinforcement learning or verifiers, the failure mode of unconstrained high-gain controllers can be directly mitigated within the standard Cross-Entropy / NLL objective using lightweight theoretical regularizations:

### 4.1 Minimal-intervention / kinetic energy penalty
In optimal control theory (Linear-Quadratic Regulator), controllers optimize the task objective plus a penalty on control energy. When cache modifications have zero regularization cost, the optimizer discovers violent high-gain shortcuts. Adding an $\ell_2$ penalty on cache displacement enforces a conservative, contractive policy:
$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{CE}} + \lambda_{\text{cache}} \cdot \frac{1}{|S|} \sum_{\tau} \left( \|\Delta K_\tau\|_2^2 + \|\Delta V_\tau\|_2^2 \right)$$
When the processor is uncertain, $\Delta S \to 0$, rendering the processor passive by default and eliminating the compounding degradation tax.

### 4.2 Cache jitter during teacher-forcing (denoising auto-regulation)
To break the assumption of pristine gold inputs without full rollout generation, inject small Gaussian noise or dropout into the gathered KV cache before processor forward execution:
$$S_{\text{input}} = S + \epsilon, \quad \epsilon \sim \mathcal{N}(0, \sigma^2 \mathbf{I})$$
$$S^* = S + \text{Processor}(S_{\text{input}})$$
Optimizing standard downstream cross-entropy from $S^*$ forces the processor to learn a **contractive mapping** (denoising score matching) that filters representation noise rather than amplifying it.

### 4.3 Base-model KL anchor (prediction fidelity loss)
To preserve the calibrated pre-trained arithmetic abilities of the frozen backbone, penalize divergence between the base backbone's logits and the processor-augmented logits:
$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{CE}} + \beta \cdot D_{\text{KL}}\left( P_{\text{base}}(y \mid x) \parallel P_{\text{with\_CP}}(y \mid x) \right)$$
The CP is only permitted to alter representations when it yields substantial cross-entropy gains, preventing it from corrupting tokens the base model already predicts with high confidence.

### 4.4 Drop-processor stochastic bypass
Randomly bypass the Cache Processor with probability $p_{\text{drop}} \in [0.2, 0.5]$ during training ($S^* = S$). This prevents the downstream attention layers from developing fragile co-dependencies on transient processor artifacts.

### 4.5 Value-only streaming constraint (`update_stream: 'v'`)
Updating keys ($\Delta K$) changes the dot-product similarity matrix $Q K^T$, which can misdirect the pre-trained query heads. Constraining updates strictly to values ($V^* = V + \Delta V$) guarantees that *where* the model attends remains governed by pre-trained query-key geometry, while the processor only refines *the retrieved information payload*.

## 5. Experimental roadmap

### Phase 1: Hyperparameter and gain containment
- **LR reduction:** Lower Cache Processor peak learning rate from `1e-3` to `1e-4` (matching LoRA).
- **Update stream ablation:** Constrain updates strictly to values (`update_stream='v'`) to preserve query-key geometric alignment ($q_t \cdot k_\tau^T$) while allowing context blending.
- **Minimal intervention loss:** Add kinetic energy regularization ($\lambda_{\text{cache}} \|\Delta V\|_2^2$).
- **Gate regularization:** Apply explicit $\ell_2$ penalty or soft-clamping on gate parameters to enforce near-identity initialization ($\alpha \ll 1$).

### Phase 2: Rollout robustness and scheduled sampling
- Implement scheduled cache sampling in SFT data streams (`p_sample` ramping from 0.0 to 0.3).
- Implement cache jitter ($\sigma = 0.01$) during teacher-forced training.
- Evaluate rollout drift metrics: track cosine similarity and $\ell_2$ distance between teacher-forced cache $S^{\text{gold}}$ and free-running cache $S^{\text{gen}}$ at each cadence $P$.

### Phase 3: Alignment with RLVR / GRPO
- Freeze the base model and train the Cache Processor using GRPO on OpenMath reasoning verification.
- Compare task accuracy under 2,048-token generation against Full-SFT and LoRA-r32.

### Phase 4: Task-domain realignment
- Shift Cache Processor evaluation toward domains matching its working-memory inductive bias:
  - Long-context multi-document needle retrieval ($> 32\text{k}$ tokens).
  - Cross-window state tracking and stateful agent workspaces.
  - Multi-turn conversational memory compression.
